# V296: symmetric +25 ps hold-repair physical trial (frozen 2026-10-27)

## Motivation and measured cause
[Immutable matched routed replay #40490815519](https://github.com/sushxnthd/vektor/actions/runs/40490815519) reproduced the previous extracted slacks to 1 ps or better and identified the worst **candidate hold path as external `rf_write_data[3]` to RF flop `_10380_`**; optimized serial has external `rf_write_data[0]` to flop `_11369_`. The worst candidate setup path is a different endpoint, `issue_valid[3]`. Thus the earlier scheduler-to-operand setup diagnosis does **not** explain the remaining worst hold failure.

Original SHA-pinned full-route results: pairwise setup +74.236 ps, hold **−12.622 ps**, area 13,379.002 µm², zero cap/slew/DRC; strongest fifth-stage serial setup −751.540 ps, hold −9.430 ps, area 15,779.651 µm², one cap violation. **Both are infeasible.**

## Single intervention frozen before outcomes
Retain V296 as the only active architecture mechanism. The original two-word fixed-word proxy is **rejected**; this is a distinct *physical repair experiment* on the same V296 mechanism, not resurrection of a proven implementation. Generate exactly the original physical flow for both variants, then change exactly one common Tcl command after CTS: `repair_timing -hold` to `repair_timing -hold -slack_margin 0.025`. No other physical Tcl, RTL, netlist generation, floorplan, density, clock, IO timing, serial fifth-stage setup repair, RC scaling, RF capacity, RF ports, or issue resources change. Keep +250 ps post-CTS setup repair. Both variants receive identical hold-margin treatment. This is a 25 ps *repair target*, not a guarantee of 25 ps hold improvement.

## Predictions and kill criteria
The repair targets the input-to-RF-register hold cone. Candidate needs at least 12.622 ps recovered hold while retaining +50 ps setup slack (only 24.236 ps deterioration allowance), zero slew/cap/DRC and ≤30,000 µm². Freeze both outcomes: predicted-win regime = modest local input hold-buffer insertion with no new critical setup endpoint; predicted-no-win regime = repair induces >24.236 ps setup loss, creates electrical/DRC violations, or leaves any negative hold. The stronger serial control receives its pre-existing fifth-stage repair and the identical hold-margin intervention. **No matched feasible Pareto claim unless both contestants pass all gates**, followed by at least 1% area advantage and 50 ps setup lead. Even if both pass, no throughput or power claim without realistic deeper-bank and workload validation.

A failure is a scientific negative result; do not alter thresholds or rerun with post-hoc margins. Original holdouts remain sealed. All artifacts, including failure and censored jobs, are retained. The independent checker verifies generated Tcl/runner hashes, executed markers, RTL SHA, frozen physical metrics, and both contestant audit records. This experiment does not establish signoff for a production GPU or RTX-5090 equivalence.
