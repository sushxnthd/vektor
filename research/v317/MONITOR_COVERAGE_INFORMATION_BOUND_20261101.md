# V317 coverage-completeness falsification and fail-closed RTL (2026-11-01)

**Decision: retain only as a correctness and evidence instrument; do not promote a GPU mechanism.** This experiment was preregistered at [FROZEN_MONITOR_COVERAGE_INDETERMINACY_20261101.md](FROZEN_MONITOR_COVERAGE_INDETERMINACY_20261101.md) in commit acf043c, before the wrapper RTL and independent checker. The previous stateful write-monitor result assumed a complete physical write-event stream. This experiment makes that assumption explicit and demonstrates why it cannot be inferred from local inputs.

## Decisive information-theoretic counterexample

A snapshot caches lane 0 = 0 and requests that lane. World A has no intervening write. World B has an intervening write setting lane 0 = 1, but the monitor misses the event. The local monitor observes exactly the same inputs in both worlds, while the correct forwarded value differs. A deterministic local grant predicate that admits the snapshot in A also admits a stale value in B. This is not solved by more identity tags or larger local snapshot storage.

The independent Python checker enumerated **2, 92, and 3,176** ambiguous old/new/captured/requested/hidden-write combinations at 1, 2, and 3 lanes, respectively. Its two-lane audit also compared **256** same-information candidate/control admission configurations: predicted incremental forwarding transactions saved = **zero**. Five local Python tests passed. These are exhaustive finite-state *semantic* counts, not GPU traces, area, delay or measured throughput.

## Fail-closed RTL experiment

The new parameterized SystemVerilog wrapper adds a sticky coverage-fault bit to the previous stateful snapshot and forces zero output whenever the grant is rejected. A low coverage signal immediately blocks forwarding; the next clock poisons the entry; recovery requires a new coherent capture under a high coverage signal. The new testbench exercises all **4,096** captured/requested/written 4-lane mask triples, including live write hazards, post-write dirtiness, coverage loss and recapture, plus directed reset/namespace/capture-fault cases.

**Critical unsolved integration assumption:** coverage_ok must be generated by an independently justified, complete observer of all relevant physical writes and must remain asserted low long enough to be sampled. If a write is lost while coverage_ok incorrectly stays high, the wrapper still admits an unsafe stale value. Sub-cycle fault pulses, asynchronous clock crossings, multi-port write visibility, coherent snapshot capture, monitor distribution and actual tile-level integration are not proven. The wrapper is a contract checker, **not** a solution to complete write observation.

## Physical evidence tier and matched control

**Hosted source-pinned result:** [V317 forwarding RTL workflow #41256988174](https://github.com/sushxnthd/vektor/actions/runs/41256988174) passed on code commit b05d4f4, including five independent Python tests, **24,583** Icarus checks comparing the optimized and naive wrappers, and three matched Yosys width points. The earlier naive wrapper also passed [workflow #41256822023](https://github.com/sushxnthd/vektor/actions/runs/41256822023). Both preserve a zero-on-reject output contract.

A separately preregistered [single-mask factorization control](FROZEN_COVERAGE_SINGLE_MASK_CONTROL_20261101.md) tested whether a second full-width output mask, rather than fundamental coverage state, explained the naive cell increase:

| Lanes x bits | Existing stateful cells | Naive double-mask cells | Optimized single-mask cells | Base / naive / optimized generic depth |
|---|---:|---:|---:|---|
| 4 x 8 | 214 | 251 | **219** | 11 / 13 / 12 |
| 8 x 16 | 586 | 719 | **591** | 12 / 14 / 13 |
| 32 x 32 | 3,645 | 4,674 | **3,650** | 13 / 15 / 14 |

At 32x32, moving the guard inside the existing data mask eliminates **1,024** avoidable generic cells (one per data bit), leaving **five** extra generic cells and **one** extra flop (1,107 versus 1,106). The optimized path still adds one level to the generic logic-depth proxy. The result falsifies any claim that the naive 1,029-cell increase was an intrinsic cost of fail-closed coverage. It also demonstrates why implementation factorization and a same-function control are essential before interpreting PPA proxies.

These are **unplaced Yosys generic** cells and graph depths, not silicon area, frequency, extracted RC, dynamic power or electrical signoff. The independent coverage detector, its physical write-event distribution, CDC handling, buffering and the actual GPU register-file interface remain **unimplemented and uncosted**.

A reuse-aware baseline given the same coherent snapshot, write-event stream and coverage signal can make all the same safe forwarding decisions. Its incremental transaction disadvantage is exactly zero in this restricted model. This invalidates any proposed positive GPU throughput law for V317 forwarding; earlier synthetic 1.5x/2x results remain falsified by stronger controls.

## Decision and next physicality gate

Do not spend another run refining this forwarding wrapper unless hosted RTL finds a correctness defect. The decisive next work is an implementable architecture mechanism with a distinct physical resource advantage over an equal-information collector, dynamic bank/write-event evidence, matched timing/area and real wire/load sensitivity. Preserve V296 as the active physical/electrical direction; V287 is historical. Kernellum PR #119 is untouched.
